# Mismo-Trainer Web Pages (v1 Snapshot)

**Status:** Verified by direct reading of every servlet in `src/main/java/org/immregistries/mismo/trainer/servlet/` (21 files) plus `web.xml`, `index.html`, and `HomeServlet.java` (the shared base class). This document is the inventory `mismo-conceptual-overview.md` §14–§16 and §24.3 asked for.

This is an old Java 8 / raw `HttpServlet` app (no Spring, no JSP — confirmed no `.jsp` files exist anywhere in `src/main/webapp`) with Hibernate 3.6 accessed directly from servlets. Every page is hand-built HTML via `PrintWriter.println(...)` string concatenation. `web.xml` maps each servlet 1:1 to `/ServletName` — there are no path parameters or nested routes anywhere in this app.

**`App.java` is a red herring** — despite living in the trainer package, it's an untouched Maven-archetype "Hello World" stub, unrelated to the running webapp. The real shared plumbing is **`HomeServlet`**, which nearly every other servlet `extends`.

## 0. Shared infrastructure: `HomeServlet`

`HomeServlet` (mapped to `/HomeServlet`, and also the parent class of almost every other servlet) provides:

- **`setup(req, resp)`** — called at the top of nearly every request. Closes any pre-existing Hibernate `Session` stored under `HttpSession` attribute `"dataSession"`, opens a fresh one from a **static singleton `SessionFactory`** (built once per JVM via `AnnotationConfiguration().configure().buildSessionFactory()`), and stores it back on the session. If a `configurationId` request parameter is present, it loads that `Configuration` row and builds a `new PatientCompare(configurationScript)`, storing it in session attribute `"patientCompare"` — **this is the only mechanism by which a weight-set gets loaded into a browsing session** (see `MatchPatientServlet`/`SignatureServlet` below for what happens when it hasn't been).
- **`teardown(req, resp)`** — closes and removes the Hibernate session. Meant to run in every servlet's `finally` block; several servlets skip this (noted per-servlet below), leaking the session until the *next* request on that `HttpSession` closes it via `setup()`'s own "close old session first" guard.
- **`doHeader`/`doFooter`** — static HTML page-chrome helpers (imports `https://www.w3schools.com/w3css/4/w3.css` from a third-party CDN — an external dependency worth removing in v2 regardless of AIRA-branding plans).
- **Login/logout** — the entire authentication mechanism: `HomeServlet.doGet` with `action=Login` runs `from User where name = ? and password = ?` (plaintext comparison — see `data-model.md` §1) and sets session attribute `"user"` on success.

`TestSetServlet` additionally defines a second layer of shared session-attribute/parameter constants (`ATTRIBUTE_MATCH_SET`, `ATTRIBUTE_MATCH_ITEM_LIST`, `ATTRIBUTE_SIGNATURE_MAP`, `PARAM_MATCH_ITEM_ID`, `PARAM_MATCH_SET_ID`, etc.) that several other servlets reference by qualified name — an informal second "context" object smeared across classes via session state rather than an explicit shared service.

**Two matching libraries coexist as live dependencies:** the current `org.immregistries:mismo-match:1.1` (package `org.immregistries.mismo.match.*`, documented in `matching-engine.md`) and the older `org.immregistries:patientmatch:1.6.03` (package `org.immregistries.pm.*`). The servlets whose names end in **"Original"** deliberately exercise the *old* library side-by-side with the new one, as a regression/comparison harness — they are not simply dead duplicates of their non-"Original" counterparts.

## 1. What's actually linked from the home page

`index.html` (the static landing page, distinct from `HomeServlet`'s own dynamically-rendered menu) links only:

```
TestSetServlet, MatchPatientServlet, TestMatchingServlet, ConvertDataServlet,
DownloadHl7Servlet, CentralServlet, GenerateWeightsServlet, RandomServlet,
RandomScriptServlet, RandomForCDCServlet
```

**Not linked from primary navigation** (reachable only by direct URL): `AddressTestServlet`, `ExampleServlet`, `MatchNodeServlet`, `MatchPatientOriginalServlet` (reachable via a link generated by `TestSetOriginalServlet`), `ReviewServlet` (reachable via links generated by `TestSetServlet`), `SignatureServlet`, `TestScriptExploreServlet`, `TestSetOriginalServlet` (linked from `TestSetServlet`'s footer), `TestSetUploadServlet` (linked from `TestSetServlet`'s upload form), `WeightSetServlet` (linked from `CentralServlet`'s "Select" action). This is a real, code-confirmed picture of which tools are "front-door" vs. "diagnostic/back-door" in v1 — useful for deciding what v2's navigation should even include.

## 3. Per-servlet detail

### HomeServlet — `/HomeServlet`
Login page, dynamic tool-directory home page, and base class for the rest of the app (see §0). `action` param drives `Login`/`Logout`. **Bug:** the logout path invalidates the session and `return`s without calling `doFooter`/closing the response body — the page is left truncated (no `</html>` etc.).

### AddressTestServlet — `/AddressTestServlet`
Paste tab-delimited address rows (Excel-style) and see how `mismo-match`'s `Address` parser breaks each into number/street/apartment/city/state/zip. Pure diagnostic, no DB writes (opens/closes a Hibernate session it never uses — wasted connection churn). No auth check. Not linked from the home page.

### CentralServlet — `/CentralServlet`
The human dashboard (`doGet`, requires login) *and* the machine-to-machine API (`doPost`, **no auth at all**) for the distributed Island optimization workers. Full protocol documented in `optimization-and-islands.md`. Has a process-wide, unsynchronized static field `lastConfigurationScriptReceived` shown in the dashboard as a debug aid.

### ConvertDataServlet — `/ConvertDataServlet`
Converts arbitrary-column-order Excel-pasted patient rows into the `key=value,...` serialized format plus ready-to-paste `TEST:`/`EXPECT:`/`PATIENT A:`/`PATIENT B:` blocks, using 26 column-position parameters (note misspelled param names `adddressLine1`/`adddress2Line1`, carried through the code). No DB access. No auth.

### DownloadHl7Servlet — `/DownloadHl7Servlet`
**Broken/stale relative to its own name and docstring.** Intends to emit all patients as HL7 v2.5.1 VXU messages, but (a) queries the `patient` table, which is empty in production (see `data-model.md` §2.1) so it currently produces essentially nothing, (b) serves `text/html` with no `Content-Disposition` — it is not actually a file download despite the name, and (c) builds each MSH-10 control ID as `today + "-" + count` where `count` is **declared but never incremented**, so every emitted message would share an identical control ID. Also opens a **second, independent Hibernate `SessionFactory`** (via the older non-annotation `org.hibernate.cfg.Configuration` API) rather than reusing `HomeServlet`'s — a duplicate connection pool. No auth.

### ExampleServlet — `/ExampleServlet`
Grab-bag demo page: a JaroWinkler similarity calculator plus a form that serializes typed-in field values into the `key=value,...` patient string live. **Bug:** `doPost` delegates to `HomeServlet.doPost` (the *inherited* method) instead of its own logic — POSTing to this URL renders the login/home page, not the example content (latent, since the page's own form uses GET). Has an explicit login check (one of the few that does).

### GenerateWeightsServlet — `/GenerateWeightsServlet`
In-browser front end to the evolutionary weight-optimization engine — starts a background `World` (GA population) stored in **`ServletContext` attribute `"world"`**, i.e. one shared, application-wide, unscoped optimization run for the entire deployment, not per-user/per-session. Lets a logged-in-or-not user directly edit the global `Scorer` weights (9 form fields `"00"`–`"22"`) with no locking. **Self-documented as deprecated**: its own javadoc says *"This is the original optimization servlet. The recommendation now is to run this using the command line [`Island`]."* Full detail in `optimization-and-islands.md` §7. No auth check on the page itself (only reachable via a logged-in-gated home-page link).

### MatchNodeServlet — `/MatchNodeServlet`
Standalone demo of a single `SimilarMatchNode` in isolation — type two values, see the similarity score, plus an auto-generated table of 10,000 random first-name pairs bucketed by score (recomputed fresh, expensively, on every page load). No DB, no auth. Not linked from home page.

### MatchPatientOriginalServlet — `/MatchPatientOriginalServlet`
Runs one Patient-A/B comparison through the **legacy `org.immregistries.pm.*` library**, using a large hardcoded weight-script constant (`TestSetOriginalServlet.ORIGINAL_CONFIG`) rather than the session's loaded `Configuration`. The old-library counterpart to `MatchPatientServlet` (see §0's "Original" note) — not a dead duplicate. **Bug:** never calls `teardown()` — no `finally` block — leaking the Hibernate session until the next request. No auth check; not linked from the home page (reachable via links `TestSetOriginalServlet` generates).

### MatchPatientServlet — `/MatchPatientServlet`
**The primary single-pair diagnostic** — full A/B field comparison, per-node signal/score breakdown across all four networks, overall result, and the signature bit-encoding table. Uses the **current** `mismo-match` library via the session's `ATTRIBUTE_PATIENT_COMPARE`. **Will throw an unhandled NPE if no `Configuration` was ever loaded into the session** (no null-guard before use) — a real first-time-user trap, since nothing forces a visit to `CentralServlet`/`WeightSetServlet` first. No auth check, despite being the flagship page.

### RandomForCDCServlet — `/RandomForCDCServlet`
Bulk synthetic-test-case generator laid out as a wide spreadsheet-style HTML table (44+ columns) matching a specific external request from a CDC deduplication project. Heavy logic duplication with `RandomScriptServlet` (near-identical scoring-threshold `if` chains, prime candidate for extraction in v2). No DB writes — output is meant to be copy-pasted elsewhere. No auth.

### RandomScriptServlet — `/RandomScriptServlet`
The **bulk generator that most likely produced the ~9,000-row production `match_item` corpus** — iterates every `Typest.Condition` × `Typest.Type` × `Typest.Type` combination, scores each synthetic pair live, and emits ready-to-upload `TEST:`/`EXPECT:`/`PATIENT A:`/`PATIENT B:` script blocks (same format `TestSetUploadServlet` ingests). Likely bug: the "different"-pair (`C`) column's pass/fail indicator reuses the `B`-pair's comparison result instead of its own. No DB writes (output must be manually copy/pasted into `TestSetUploadServlet`). No auth.

### RandomServlet — `/RandomServlet`
Interactive single-triple tuner — pick `Typest.Type`/`Typest.Condition` per patient (A/B "same"/C "different"), see live scores, and follow generated "Compare" deep links into `MatchPatientServlet`. Those links **inherit `MatchPatientServlet`'s NPE trap** if no configuration has been loaded yet. No DB, no auth.

### ReviewServlet — `/ReviewServlet`
Post-run analysis: buckets failing test cases from the most recent `TestSetServlet`/`TestMatchingServlet` run into six "should X but got Y" categories, plus groups of same-signature-but-different-expected-outcome cases (a heuristic for finding inconsistently-labeled training data). **Entirely dependent on session state left behind by other servlets** — reads nothing from the DB directly, just `TestSetServlet`'s cached session attributes; shows a placeholder message if visited out of order. Explicit login check present. Not linked from the home page directly (reachable via `TestSetServlet`).

### SignatureServlet — `/SignatureServlet`
Paste a raw signature string, see the decoded per-node scores (via `ReverseSignatureUtil`, see `matching-engine.md` §9) without needing an actual patient pair. **Same NPE trap as `MatchPatientServlet`** if no configuration is loaded. No auth check. Not linked from home page.

### TestMatchingServlet — `/TestMatchingServlet`
Runs an entire test set — either a DB-backed `match_set` (if logged in) or one of eight hardcoded classpath script files `MIIS-B/C/D/E/E2/E3/F1/F2.txt` (if anonymous) — against the loaded configuration, producing a pass/fail table, the 3×3 confusion-count matrix (via `Scorer`, see `optimization-and-islands.md` §3), and an overall percentage score. **The one servlet deliberately designed to work without login** (branches its own behavior on `user == null`). **Bug:** no `finally`/`teardown()` at all — leaks the Hibernate session opened by `setup()`.

### TestScriptExploreServlet — `/TestScriptExploreServlet`
Data-quality checker over the eight hardcoded `MIIS-*.txt` files — flags any case labeled `"Match"` whose name/DOB fields actually differ between A and B, and auto-downgrades them **in memory only** (not persisted — the corrected output must be manually copied and re-uploaded via `TestSetUploadServlet` to stick). No auth, not linked from home page.

### TestSetOriginalServlet — `/TestSetOriginalServlet`
Runs an entire loaded `match_set` through both the current result (already cached on session) and a fresh legacy-library (`org.immregistries.pm.PatientMatcher`) result, side by side, for old-vs-new regression comparison. Requires a `match_set` to already be loaded via `TestSetServlet` first. Explicit login check. Linked from `TestSetServlet`'s footer.

### TestSetServlet — `/TestSetServlet`
**The central hub for managing `match_set`/`match_item` data**: create sets, browse items one at a time with Previous/Next/Next-Unset/Next-Fail navigation, set/override each item's expected classification, view the whole set's scorecard, and download a set as a `.txt` script (`Content-Disposition: attachment`, filename built directly from the unsanitized set label). Explicit login check. **Note:** `session.getAttribute(sublistName)` uses a raw request parameter as a session-attribute lookup key — a narrow injection-adjacent pattern, low blast radius today (only reads six pre-defined lists `ReviewServlet` sets) but worth tightening in v2.

### TestSetUploadServlet — `/TestSetUploadServlet` (extends `TestSetServlet`)
Handles the actual multipart file upload of a `.txt` script into a chosen `match_set`, upserting each `TEST:` block into `match_item` by label. **No auth check of its own** (doesn't call `super.doPost`, so it inherits none of `TestSetServlet`'s protections) — reachable by an unauthenticated POST despite only being exposed via a logged-in-only form. **No try/catch/finally around the whole method** — any exception (e.g. a blank `dataSource`, a malformed `matchSetId`) produces an unhandled 500 and skips `teardown()`, leaking the session. Declares a dead `uploadDirString` field (default `"/temp"`) tied to an init-param `web.xml` never actually defines — files are in fact parsed entirely in memory and never written to disk, despite a stale comment describing a "save to temp directory" step.

### WeightSetServlet — `/WeightSetServlet`
Lets a user manually paste/edit a full weight-set YAML directly and load it into the session as the active configuration — the manual-override counterpart to `CentralServlet`'s "Select" links (which pass `configurationId` and are auto-loaded by `HomeServlet.setup()`). Explicit login check. Declares a second, **dead** duplicate `getSessionFactory()` (copy-pasted from `DownloadHl7Servlet`, but Java static-method-hiding means it's never actually invoked — harmless but confusing leftover). Emits duplicate closing `</body></html>` tags after `HomeServlet.doFooter` already closed them (invalid but harmless HTML).

## 4. Cross-cutting findings for v2

1. **No CSRF protection anywhere.** Every state-changing action is a plain form GET/POST with no token.
2. **No real authentication framework** — a `user` table with plaintext passwords compared via raw HQL, session-attribute "logged in" flag, no expiry policy, no rate limiting, no roles/permissions (anyone who can log in has full access to everything).
3. **Auth enforcement is inconsistent and mostly a UI convention, not a security boundary.** Only `CentralServlet.doGet`, `ExampleServlet`, `ReviewServlet`, `TestSetServlet`, `TestSetOriginalServlet`, and `WeightSetServlet` explicitly redirect anonymous users. Every other servlet — including `CentralServlet.doPost`, the machine-to-machine config-write API — is reachable and fully functional with **zero authentication**, by direct URL, regardless of what the home page chooses to link.
4. **No HTML-escaping anywhere.** All 21 servlets inject user- and DB-sourced strings (`match_item.label`/`.description`, `user.name`, pasted configuration scripts, etc.) directly into hand-built HTML — persistent XSS is plausible wherever a `match_item` label or description created by one user is later rendered to another logged-in user.
5. **Hibernate session lifecycle is fragile and inconsistent**, in three different flavors: the standard `setup()`/`teardown()` pattern; ad hoc locally-opened/closed sessions (`CentralServlet.doPost`); and two servlets that declare their own second static `SessionFactory` (`DownloadHl7Servlet` — actually used, meaning a duplicate live connection pool; `WeightSetServlet` — dead code). At least `MatchPatientOriginalServlet`, `TestMatchingServlet`, and `TestSetUploadServlet`'s exception path never call `teardown()`, leaking sessions until the next request happens to close them.
6. **Multiple servlets NPE on the natural first-time-user path** (`MatchPatientServlet`, `SignatureServlet`, and transitively any "Compare" link `RandomServlet` generates) because `ATTRIBUTE_PATIENT_COMPARE` is read from session with no null-guard — a user who hasn't first visited `CentralServlet`/`WeightSetServlet` gets a raw stack trace instead of a helpful message.
7. **Hardcoded classpath resource filenames scattered through the code**: `MIIS-E2.txt` (`GenerateWeightsServlet`), the eight `MIIS-*.txt` files (`TestMatchingServlet`, `TestScriptExploreServlet`), a dead `"/temp"` upload-dir default (`TestSetUploadServlet`). None of this is externally configurable.
8. **Shared mutable global state with no synchronization**: `CentralServlet.lastConfigurationScriptReceived` (static, JVM-wide), `GenerateWeightsServlet`'s application-scoped `World` running a live background thread started by an ordinary GET, and direct in-place mutation of `Scorer`'s static weight matrix from request parameters (race condition under concurrent users — detailed in `optimization-and-islands.md`).
9. **Copy-pasted dead JavaScript** (a `toggleLayer(whichLayer)` function) appears in six servlets; only `GenerateWeightsServlet` actually wires it to any clickable element.
10. **A recurring markup bug** — an `<input ... value="..."` tag missing its closing `>` — is independently copy-pasted across `MatchPatientOriginalServlet`, `MatchPatientServlet`, and `SignatureServlet`. A single shared rendering helper in v2 would fix all three occurrences at once.
